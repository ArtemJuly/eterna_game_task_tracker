# Этерна (Eterna) — брифинг для консультации по новому функционалу

## Что это

Личный трекер продуктивности в формате RPG. Веб-приложение (SPA), без бэкенда — всё
хранится в localStorage браузера. Единственный пользователь — Артём, ведёт свои
задачи/проекты/награды и прокачивает "персонажа" за счёт выполненной работы.

## Стек

- React + TypeScript + Vite
- Tailwind CSS v4 (CSS-first `@theme`, тёмная тема)
- React Router v6 (`BrowserRouter`, вложенные роуты через `<Outlet>` в `Layout`)
- Персистентность: кастомный `createStore` (`src/utils/store.ts`) — реактивное
  хранилище на `useSyncExternalStore` с ленивой инициализацией (чтобы не было гонки
  с seed-данными при первом запуске) и синхронной записью в localStorage
- Никакого бэкенда, никакой аутентификации

## Экраны (роуты, `src/App.tsx`)

| Роут | Страница | Смысл |
|---|---|---|
| `/` | Dashboard | уровень персонажа, XP/этерны, графики за 14/30 дней, активные проекты, ближайшие задачи |
| `/tasks` | Tasks | список задач (только верхнего уровня), фильтры по статусу/проекту |
| `/tasks/:id` | TaskDetail | карточка задачи с drill-down в подзадачи (неограниченная вложенность) |
| `/projects` | Projects | список проектов-карточек |
| `/projects/:id` | ProjectDetail | карточка проекта + список задач |
| `/rewards` | Rewards | магазин наград за этерны |
| `/history` | History | лента всех начислений/событий |
| `/settings` | Settings | настройки помидора + "опасная зона" (сбросы данных) |

## Игровая экономика

- **XP** — растит уровень персонажа (`src/utils/levels.ts`, 8 уровней от "Новичок" до
  "Создатель систем", пороги 0/300/700/1200/2000/3000/5000/8000)
- **Этерны (✦)** — внутренняя валюта, тратится на покупку наград в Rewards
- Оба ресурса начисляются за: выполнение задачи, выполнение проекта, завершение помидора

### Множители награды за задачу (`src/utils/taskRewards.ts`)

Два независимых, перемножаемых множителя:

1. **⭐ Фокус дня** (×2) — задача отмечена как одна из "3 главных задач на сегодня"
   (`task.focusDate === today`, максимум 3 в день, сбрасывается на новый день)
2. **🚀 Спринт-проект** (×1.2) — задача принадлежит одному из проектов, отмеченных как
   "спринт" (максимум 3 проекта одновременно, переключается вручную и не привязано к дате)

Если оба множителя активны — они перемножаются: ⭐🚀×2.4. Итоговые XP/этерны
округляются (`Math.round`).

## Модель данных (`src/types/index.ts`)

- **Task** — `title`, `description`, `projectId`, `parentTaskId` (для дерева подзадач
  любой глубины), `status` (`planned|in_progress|done|cancelled`), `xp`, `eternas`,
  `focusDate`
- **Project** — `title`, `goal`, `deadline`, `status` (`active|done`), собственные `xp`/
  `eternas` за завершение проекта, `isSprint`
- **Reward** — `title`, `costEternas`, `costMoney`, `status`
  (`wanted|saving|available|purchased|cancelled`)
- **HistoryEntry** — лог всех событий (`task_done`, `project_done`, `reward_purchased`,
  `task_cancelled`, `pomodoro_completed`) с дельтами XP/этерн
- **PomodoroSession** / **ActivePomodoro** — помидор как отдельная сущность
  (см. ниже), не привязан жёстко к задаче навсегда
- **Settings** — длительность помидора, бонус XP/этерн за помидор

Все поля, добавленные в процессе разработки, нормализуются через `?? default` при
чтении (и в хуках, и в seed-данных) — это принципиальный паттерн миграции старых
данных без бэкенд-схемы.

## Помидоро-таймер — особенности

Помидор — самостоятельная сущность (`ActivePomodoro`), не жёстко привязанная к задаче:

- Может быть `running` или `paused`
- При завершении/отмене/удалении задачи, на которой крутится помидор, он не
  сбрасывается, а **ставится на паузу** и может быть продолжен на другой задаче
  (кнопка "▶ Продолжить")
- Одновременно может выполняться только один помидор во всём приложении
- Виджет активного помидора живёт в сайдбаре (`SidebarPomodoro.tsx`), виден с любой
  страницы
- За каждый завершённый помидор — минимальный бонус XP/этерн (настраивается в Settings)
- Компоненты отрисовки таймера используют `useLayoutEffect` для синхронизации текущего
  времени сразу при старте — это защита от короткой вспышки неверных чисел, если
  компонент долго простаивал (была реальная баг, уже исправлена)

## Задачи и вложенность

- `parentTaskId: string | null` — неограниченная глубина вложенности подзадач
- Навигация — drill-down в карточку (`TaskDetail.tsx`), а не разворачивание списком
- Вся строка задачи/проекта кликабельна для перехода (не только заголовок), вложенные
  интерактивные элементы (звезда, помидор, кнопки статуса) останавливают всплытие клика
- Для карточек-`<Link>` (react-router) недостаточно `stopPropagation()` — нужен ещё и
  `preventDefault()`, иначе браузер сделает hard-navigation

## Графики на Dashboard

Лёгкие кастомные SVG-компоненты `AreaChart`/`BarChart` (сознательно без тяжёлых
чарт-библиотек) — задачи выполнено, помидоры (+минуты), XP, этерны, за окна 14/30 дней.

## Дизайн-система

Тёмная тема, CSS-переменные: `--bg`, `--surface`, `--border`, `--text-primary`,
`--text-muted`, `--accent-xp` (фиолетовый), `--accent-eternas` (янтарный), `--success`
(зелёный), `--danger` (красный). Компонент `Badge` с тонами
`default|xp|eternas|success|danger|muted`.

## Соглашения по разработке (важно учитывать при обсуждении новых фич)

- Никакого бэкенда — все идеи должны работать поверх localStorage одного пользователя
- При добавлении нового поля в тип — сразу предусмотреть `?? default` в нормализации
  и в seed, иначе будет краш на старых данных
- Не тянуть тяжёлые библиотеки (чарты, датапикеры и т.п.) без явной необходимости —
  явное пожелание держать бандл лёгким
- Не готовые бэклог-идеи, которые обсуждались, но НЕ реализованы: более крупная
  экономика "XP vs Заслуги vs Наследие", AI game-master роли, дневник с треками
  развития, персонажные статы, AI-профиль личности, параллельные треки, PIN-лок,
  сезоны, фото наград — это черновой личный вижн-документ, не текущий скоуп
