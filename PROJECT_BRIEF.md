# Этерна (Eterna) — статус проекта и брифинг для консультации

## Что это

Личный трекер продуктивности в формате RPG. Веб-приложение (SPA), без бэкенда — всё
хранится в localStorage браузера. Единственный пользователь — Артём, ведёт свои
задачи/проекты/награды/треки развития и прокачивает «персонажа» за счёт выполненной
работы.

## Зачем этот документ

Готовится обсуждение новой фичи: **как встроить ИИ в оценку стоимости задач** (то есть
в подбор XP/этерн при создании задачи, вместо ручного ввода). Документ описывает
текущее состояние проекта, чтобы консультация могла сразу опираться на реальные
ограничения и данные, а не переизобретать контекст.

## Стек

- React + TypeScript + Vite
- Tailwind CSS v4 (CSS-first `@theme`, тёмная тема)
- React Router v6 (`BrowserRouter`, вложенные роуты через `<Outlet>` в `Layout`)
- Персистентность: кастомный `createStore` (`src/utils/store.ts`) — реактивное
  хранилище на `useSyncExternalStore` с ленивой инициализацией и синхронной записью в
  localStorage
- **Никакого бэкенда, никакой аутентификации** — это ключевое ограничение для любой
  ИИ-фичи: вызов модели пойдёт либо прямо из браузера (ключ API светится клиенту, это
  проблема), либо потребует завести хоть какой-то серверный прокси, чего сейчас в
  проекте нет вообще

## Игровая экономика

- **XP** — растит уровень персонажа (`src/utils/levels.ts`, 8 уровней от «Новичок» до
  «Создатель систем», пороги 0/300/700/1200/2000/3000/5000/8000)
- **Этерны (✦)** — внутренняя валюта, тратится на покупку наград в Rewards
- Оба ресурса начисляются за: выполнение задачи, выполнение проекта, завершение
  помидора, серию повторяющихся задач

### Как сейчас назначается стоимость задачи (это и есть то, что предстоит заменить/дополнить ИИ)

В `TaskModal.tsx` при создании/редактировании задачи пользователь **вручную** вписывает
два числа — `xp` (по умолчанию 20) и `eternas` (по умолчанию 5). Никакой логики подбора
значений сейчас нет вообще — ни эвристик, ни истории, ни ИИ. Это открытое поле для
новой фичи.

### Множители награды за задачу (`src/utils/taskRewards.ts`)

Применяются поверх введённого `xp`/`eternas` при выполнении, а не при создании:

1. **⭐ Фокус дня** (×2) — задача отмечена одной из «3 главных задач на сегодня»
2. **🚀 Спринт-проект** (×1.2) — задача принадлежит одному из ≤3 проектов-спринтов

Множители перемножаются (⭐🚀×2.4), итог округляется (`Math.round`).

### Серии повторяющихся задач (`src/utils/recurrence.ts`)

Задача может быть повторяющейся (`recurrenceIntervalDays`, пресеты
ежедневно/через день/раз в неделю/своё число дней). При выполнении в срок серия растёт,
после срыва — сбрасывается на 1. Растущий бонус: `шаг × (длина серии − 1)`, шаг
настраивается в Settings (по умолчанию 5 XP / 5 ✦). При пересечении вех (3/7/14/30
подряд) — бейдж со звёздами и отдельный праздничный тост.

## Модель данных (`src/types/index.ts`)

- **Task** — `title`, `description`, `projectId`, `parentTaskId` (дерево любой
  глубины), `status` (`planned|in_progress|done|cancelled`), `xp`, `eternas`,
  `focusDate`, `recurrenceIntervalDays`, `nextDueDate`, `streakCount`,
  `trackLinks: {trackId, stageId}[]`
- **Project** — `title`, `goal`, `deadline`, `status` (`active|done` — это про
  завершённость), `xp`/`eternas` за завершение, `isSprint` (топ-3 приоритет,
  ×1.2), `isActive` (топ-5 «в фокусе прямо сейчас», независимая метка, просто
  визуально приглушает неактивные — **не закоммичено**)
- **Track** / **TrackStage** — трек развития (например, «Data Scientist») — линейная
  последовательность этапов (например, «Математик»), каждый этап — 3 внутренних уровня
  (I/II/III) с порогами XP 0/100/250 (`utils/trackLevels.ts`). Переход между этапами —
  только вручную, кнопка появляется по достижении уровня III. Задача может быть
  привязана к нескольким (трек, этап) одновременно — XP при выполнении делится между
  ними поровну (`useTracks.ts` → `applyTrackXp`) — **не закоммичено**
- **Reward** — `title`, `costEternas`, `costMoney`, `status`
- **HistoryEntry** — лог всех событий (`task_done`, `project_done`,
  `reward_purchased`, `task_cancelled`, `pomodoro_completed`) с дельтами XP/этерн —
  это готовый источник исторических данных «сколько реально стоила задача»
- **PomodoroSession** — фактическое время работы над задачей (`taskId`,
  `durationMinutes`, `status`) — тоже готовый сигнал «сколько реально заняло времени»,
  потенциально полезный как обратная связь для калибровки ИИ-оценки
- **Settings** — длительность помидора, бонусы за помидор/серию

Принципиальный паттерн: любое новое поле нормализуется через `?? default` при чтении
(в хуках и в seed) — иначе краш на старых данных без бэкенд-миграций.

## Что уже есть из данных, на которые может опираться ИИ-оценка

Если будете обсуждать эвристики/промпт для оценки стоимости — вот что реально
доступно на клиенте без похода на сервер:

- Текст задачи (`title` + `description`)
- Проект и его цель (`project.goal`), трек и этап, если привязаны
- **История уже выполненных задач** с их `xp`/`eternas` и фактическим временем
  (`PomodoroSession.durationMinutes` по `taskId`) — потенциальный датасет для
  few-shot-примеров или калибровки «похожая задача весила X»
- Текущий уровень персонажа/этапа трека (для относительной, а не абсолютной оценки)

Чего нет: никакого текстового поля «оценка сложности» или тегов/категорий у задач
сейчас не существует — если ИИ-оценке понадобится такая метаинформация, её негде
взять без нового поля в `Task`.

## Помидоро-таймер — особенности

Помидор — самостоятельная сущность (`ActivePomodoro`), не жёстко привязанная к задаче:
может быть `running`/`paused`, при завершении/отмене/удалении задачи не сбрасывается, а
ставится на паузу и может быть продолжена на другой задаче. Один активный помидор на
всё приложение. Виджет — в сайдбаре (`SidebarPomodoro.tsx`), таймер использует
`useLayoutEffect` для синхронизации времени при старте (защита от кратковременной
вспышки неверных чисел — был реальный баг, пофикшен).

## Задачи и вложенность

`parentTaskId: string | null` — неограниченная вложенность, навигация через drill-down
карточки (`TaskDetail.tsx`). Вся строка задачи/проекта кликабельна (не только
заголовок); для карточек-`<Link>` нужен `preventDefault()` + `stopPropagation()` на
вложенных интерактивных элементах, иначе будет hard-navigation.

## Графики на Dashboard

Лёгкие кастомные SVG `AreaChart`/`BarChart` (сознательно без тяжёлых чарт-библиотек) —
задачи выполнено (по истории, не по live-статусу — важно для повторяющихся задач),
помидоры (+минуты), XP, этерны, за окна 14/30 дней.

## Дизайн-система

Тёмная тема, CSS-переменные `--bg`, `--surface`, `--border`, `--text-primary`,
`--text-muted`, `--accent-xp` (фиолетовый), `--accent-eternas` (янтарный), `--success`
(зелёный), `--danger` (красный). `Badge` с тонами
`default|xp|eternas|success|danger|muted`.

## Соглашения по разработке

- Никакого бэкенда — новые идеи должны работать поверх localStorage одного
  пользователя, либо явно обсуждать появление сервера (для ИИ-фичи это, скорее всего,
  неизбежно — ключ провайдера нельзя класть в клиентский бандл)
- Новое поле в типе → сразу `?? default` в нормализации и в seed
- Не тянуть тяжёлые библиотеки без явной необходимости — бандл держим лёгким
- Не реализованные идеи из старого личного вижн-документа (не текущий скоуп, но фон
  для понимания направления): экономика «XP vs Заслуги vs Наследие», AI game-master
  роли, дневник, персонажные статы, AI-профиль личности, PIN-лок, сезоны, фото наград
