# План этапов трека (🤖 Предложить план)

По названию и цели трека развития предлагает последовательность этапов (с названием и коротким
описанием каждого) — черновой roadmap от текущего состояния к цели.

## Где

Кнопка "🤖 Предложить план" на странице трека (`/tracks/:id`), рядом с "+ Добавить этап".

## Файлы

- [`src/utils/aiTrackPlan.ts`](../../src/utils/aiTrackPlan.ts) — промпт и парсинг
- [`src/pages/TrackDetail.tsx`](../../src/pages/TrackDetail.tsx) — вызов и обработка результата
- [`src/hooks/useTracks.ts`](../../src/hooks/useTracks.ts) — `addStages()`, массовое добавление
  этапов в трек

## Как работает

1. По клику `generateTrackPlan(trackTitle, trackGoal, existingStageTitles, apiKey)` получает:
   название трека, его цель (`Track.goal`, может быть пустой), и названия **уже существующих** этапов
   по порядку — чтобы план продолжался после них, а не повторял их с нуля.
2. Промпт просит 4-8 новых этапов, "конкретных, реалистичных, в логическом порядке возрастания".
   Если цель не задана — модель ориентируется просто на название трека. Для каждого этапа —
   заголовок + 1-2 предложения описания ("что конкретно значит его пройти").
3. Ответ — JSON-массив `[{"title", "description"}]`, обрезается до 10 элементов (`MAX_STAGES`),
   элементы без непустого `title`/`description`-строки отбрасываются.
4. Результат уходит в `addStages(trackId, stages)` — этапы добавляются в конец списка этапов трека,
   каждый с `xp: 0, level: 1` (как у вручную созданных). Дальше с ними можно делать всё то же самое,
   что и с любыми этапами: переименовать, поправить описание, переставить местами, удалить.

Переход между этапами (`advanceStage`) как был, так и остался полностью ручным — AI только предлагает
содержание, но не продвигает пользователя по треку.

## Пример

Трек "Карьера", цель "Стать исполнительным директором отдела разработки", без существующих этапов →
получили 8 этапов от "Овладеть основными навыками разработки" до "Стать исполнительным директором
отдела разработки", с логичной прогрессией через Tech Lead → Engineering Manager → Director.

При повторном вызове с уже существующими этапами (например Junior→Middle→Senior разработчик) —
план не повторяет их, а продолжает с Tech Lead и далее.

## Ограничения

- **Один этап ≠ произвольно большая единица работы.** Не путать со "стоимостью" — у этапов трека нет
  собственного XP-бюджета уровня "оценки задачи": XP этапу начисляется только через привязанные к нему
  задачи (`TrackLink`), план лишь формулирует содержание, не оценивает объём.
- Планировать стоит по одному треку за раз — промпт не знает о других треках пользователя и не
  балансирует между ними.
