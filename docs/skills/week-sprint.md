# Недельный спринт (📅 Недельный спринт)

Собирает список задач на текущую неделю (~5-15 штук), исходя из иерархии приоритета проектов/треков
и того, к каким целям в Карте целей они относятся. В отличие от [плана на день](./day-plan.md), сроки
здесь — вторичный критерий: главное — что задача двигает приоритетную цель.

## Где

"🤖 AI-агент" → "📅 Недельный спринт" на `/tasks`.

## Файлы

- [`src/utils/aiWeekSprint.ts`](../../src/utils/aiWeekSprint.ts) — промпт и парсинг
- [`src/components/WeekSprintModal.tsx`](../../src/components/WeekSprintModal.tsx) — UI (почти
  дословно повторяет структуру `DayPlanModal.tsx`)
- [`src/hooks/useWeekSprint.ts`](../../src/hooks/useWeekSprint.ts) — персистентность, привязана к
  началу недели, а не к дате
- [`src/utils/goalMap.ts`](../../src/utils/goalMap.ts) — `findEnclosingGoalTitle`, общий хелпер
  (используется и на Dashboard) для поиска ближайшей узловой "цели" вверх по дереву Карты целей
- [`src/types/index.ts`](../../src/types/index.ts) — `WeekSprint`/`SprintItem`

## Как работает

### Неделя

`getWeekStartDateString()` ([`src/utils/today.ts`](../../src/utils/today.ts)) — понедельник текущей
недели (ISO, неделя с понедельника). Спринт хранится как `{weekStart, items}`; `useWeekSprint()`
отдаёт пустой список, если сохранённый `weekStart` не совпадает с текущим — точно так же, как
`useDayPlan()` истекает по дате, только с недельной гранулярностью.

### Кандидаты и приоритетный контекст

Кандидаты — те же открытые задачи (`planned`/`in_progress`) с проектом/треком/сроком, что и в дне,
но топ-проектов/треков берётся больше (5 и 3 против 3 и 2 у дневного плана — неделя шире), и к каждому
добавляется **`enclosingGoalTitle`** — название ближайшей цели вверх по дереву Карты целей
(`findEnclosingGoalTitle(nodes, nodes.find(n => n.type === 'project' && n.projectId === p.id))`).
Именно это отличает спринт от дня: модель видит не только "проект X приоритетнее проекта Y", но и
"проект X — часть цели «Карьера»".

### Промпт

Инструкция: главный критерий — иерархия приоритета + связь с целью, срок — вторичный. Разумный размер
5-12 задач, максимум 15 (`MAX_SUGGESTIONS`). Как и везде — пустой список тоже валиден, причина на
каждую задачу обязательна, ссылки на задачи только по номеру в списке (тот же приём, что в
[дне](./day-plan.md#матчинг-по-номеру-не-по-id)).

### Персистентность и редактирование

Идентично дню — стор в `localStorage`, список в модалке считается из `weekSprint` + актуальных
`tasks` (значит тоже "усыхает" по мере выполнения задач), ✕ на каждом пункте, поиск снизу для
ручного добавления, "🔄 Обновить спринт" для полной регенерации.

### Обратная связь в план на день

`weekSprint` читается в [`DayPlanModal.tsx`](../../src/components/DayPlanModal.tsx) — при сборе
кандидатов для дня каждая задача помечается `isInSprint: sprintTaskIds.has(task.id)`, и в промпте дня
эти задачи получают отметку `[СПРИНТ]` с инструкцией отдавать им предпочтение в первую очередь.
Однонаправленная связь: спринт влияет на день, день не влияет на спринт.

## Пример

Топ-проект "Исполнительный директор" (часть цели "Карьера", отмечен как спринт-проект) и "Диссертация"
(часть цели "Наука") → спринт выбрал по 2 задачи каждого с причинами вроде "двигает цель «Карьера»
через топ-проект" и "просроченная задача, требует немедленного внимания" — бытовые и посторонние
задачи (почта, корм коту, код-ревью пет-проекта) не попали.

## Ограничения

- `enclosingGoalTitle` ищется только для узлов, у которых есть прямая связь `project`/`track` в Карте
  целей (`useGoalMap`) — если проект не добавлен в Карту целей как узел, модель увидит только его
  название/цель/дедлайн, без более широкого контекста.
- Треки без этапов исключаются из кандидатов (`t.stages.length > 0`) — модели нечего показать в
  качестве "текущего этапа".
