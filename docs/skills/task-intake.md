# Разбор списка задач (📋 Разобрать список задач)

По вставленному произвольному тексту (список дел, заметка, что угодно) создаёт сразу несколько задач:
режет текст на отдельные пункты, оценивает каждому XP/этерны и подбирает проект/трек — то же самое,
что делает [оценка одной задачи](./task-estimate.md), но пакетно.

## Где

"🤖 AI-агент" → "📋 Разобрать список задач" на странице `/tasks`.

## Файлы

- [`src/utils/aiTaskIntake.ts`](../../src/utils/aiTaskIntake.ts) — промпт и парсинг
- [`src/components/TaskIntakeModal.tsx`](../../src/components/TaskIntakeModal.tsx) — двухшаговый UI

## Как работает

**Шаг 1 — ввод.** Textarea, куда вставляется текст в любом формате (буллеты, нумерация, просто
строки). Кнопка "🤖 Разобрать список".

**Разбор** (`parseTaskList`):
1. В промпт идёт список активных проектов и треков (кандидаты для сопоставления — та же логика,
   что и в оценке одной задачи, те же формулировки правил через `buildRewardRubricLines()`) плюс сам
   сырой текст.
2. Модель просится разбить текст на задачи: "каждый пункт списка, строка или явно отдельная мысль —
   одна задача", придумать короткие `title`/`description`, оценить `xp`/`eternas` по общей рубрике,
   сопоставить `projectTitle`/`trackTitle` по тем же правилам "лучше `null`, чем притянутое совпадение".
3. Ответ — JSON-массив. Каждый элемент валидируется: `title` обязателен и непустой; если `xp`/`eternas`
   пришли не числом — подставляется дефолт (20/5, как в ручном создании задачи), а не отбрасывается вся
   задача. Максимум **30** задач за один разбор (`MAX_TASKS`) — лишнее отрезается, а не отклоняется
   целиком.
4. Если после фильтрации не осталось ни одной задачи — `AiEstimateError('AI не нашёл в тексте ни одной задачи')`.

**Шаг 2 — предпросмотр.** Каждый черновик — редактируемая карточка: title, description, XP, этерны —
все поля обычные `input`/`textarea`, можно поправить что угодно до создания. Select проекта
предзаполнен, если было совпадение (сматчено через `titleMatches`, как и в одиночной оценке), но
доступен для ручной смены. Трек показывается бейджем (не редактируется здесь — донастраивается потом
через обычную карточку задачи). Крестик у карточки — просто убирает черновик из списка на создание,
ничего не сохраняя.

Кнопка "Создать N задач" вызывает `addTask()` в цикле по оставшимся черновикам — каждая уходит как
самостоятельная (без иерархии, `parentTaskId: null`) задача со статусом `planned`.

## Пример

Вход:
```
- Исправить правки научного руководителя
- Разработать агента для автоматизации отчётов
- Купить корм для кота
```
Выход (в реальном тесте): первая задача → проект "Диссертация", вторая → трек "Агенты", третья —
`projectTitle: null, trackTitle: null` (нет связи, и это правильно).

## Ограничения

- Список плоский — иерархия подзадач по отступам/вложенности из текста не распознаётся, всё уходит
  верхнеуровневыми задачами.
- `max_tokens: 2000` на запрос — при очень длинном списке (близко к 30 задачам) ответ модели может не
  влезть и обрежется; в этом случае `JSON.parse` упадёт и разбор завершится ошибкой "Не удалось
  распознать ответ AI-сервиса" — стоит разбивать совсем длинные списки на несколько вставок.
