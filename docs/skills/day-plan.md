# План на день (🗓️ Спланировать день)

Подбирает 3-8 существующих открытых задач на сегодня: смесь ключевых задач топ-приоритетных
проектов/треков и тех, у которых подошёл срок. Учитывает недельный спринт (если он есть) и то,
будний сегодня день или выходной. Ничего не создаёт — только выбирает **из уже существующих** задач.

## Где

"🤖 AI-агент" → "🗓️ Спланировать день" на `/tasks`.

## Файлы

- [`src/utils/aiDayPlan.ts`](../../src/utils/aiDayPlan.ts) — промпт и парсинг (индексный матчинг,
  см. ниже)
- [`src/components/DayPlanModal.tsx`](../../src/components/DayPlanModal.tsx) — UI
- [`src/hooks/useDayPlan.ts`](../../src/hooks/useDayPlan.ts) — персистентность (localStorage,
  привязка к сегодняшней дате)
- [`src/types/index.ts`](../../src/types/index.ts) — `DayPlan`/`DayPlanItem`

## Как работает

### Матчинг по номеру, не по ID

Задачи в промпт передаются **пронумерованным списком**, и модель ссылается на выбранные задачи по
номеру (`index`), а не по `id`. Осознанное решение: `id` задач — случайные строки
(`crypto.randomUUID()`), модель может их исказить при копировании; номер по порядку в промпте —
простое целое число, которое она копирует надёжно, а код тривиально проверяет на выход за границы
диапазона.

### Кандидаты

Все задачи со статусом `planned`/`in_progress`. Для каждой в промпт идёт:
- проект (если есть) и трек+этап (если есть)
- срок (`dueDate`) и явная пометка `(ПРОСРОЧЕНА)`, если просрочена (`isTaskOverdue`)
- пометка `[СПРИНТ]`, если задача есть в текущем [недельном спринте](./week-sprint.md)
- `xp`/`eternas`

Плюс контекст:
- топ-3 приоритетных активных проекта (по существующей сортировке `projects[0..2]` — она уже
  отсортирована по `priority`), с целью/дедлайном/флагом спринт-проекта
- топ-2 приоритетных трека (аналогично, только с этапами)
- сегодняшняя дата **и** будний/выходной день (`isWeekendDateString`)

### Промпт

Инструкция: собрать смесь (а) ключевых задач топ-проектов/треков и (б) просроченных/скоро-срочных;
задачам с `[СПРИНТ]` — предпочтение в первую очередь; на выходных — аккуратнее с чисто рабочими
задачами; реалистичный размер (3-6, максимум 8, `MAX_SUGGESTIONS`); пустой список — тоже валидный
ответ, если ничего не выделяется. Для каждой задачи — одно предложение причины.

### Персистентность

Результат сохраняется в `dayPlanStore` (`localStorage`, ключ `eterna_day_plan`) как
`{date, items: [{taskId, reason}]}`. `useDayPlan()` возвращает пустой список, если сохранённая дата
не совпадает с сегодняшней — план не нужно явно чистить, он просто перестаёт быть "сегодняшним"
сам по себе на следующий день.

Список в модалке рендерится не из ответа AI напрямую, а из `todayPlan` + актуальных `tasks`
(через `useMemo`) — так что:
- прогресс виден сразу: как только задача выполнена, она пропадает из списка (фильтр по статусу
  `planned`/`in_progress`)
- повторное открытие модалки в течение дня показывает тот же план без нового запроса к API

### Редактирование

- ✕ у каждого пункта — убирает его из плана (`setDayPlan` с отфильтрованным списком)
- Поле поиска снизу — набираешь часть названия, снизу выпадают совпадения среди задач, которых ещё
  нет в плане; клик — добавляет с причиной `"Добавлено вручную"`
- Кнопка "🔄 Обновить план" (тот же "🤖 Составить план", просто другой текст) — генерирует заново,
  полностью заменяя текущий список

### Влияние на остальной UI

- [`src/utils/taskSort.ts`](../../src/utils/taskSort.ts) — `compareTasks` получил параметр
  `dayPlanTaskIds`: задачи из плана поднимаются в общем списке `/tasks` на позицию сразу после
  "⭐ фокус дня" (перед сортировкой по срочности/опыту)
- [`src/pages/Tasks.tsx`](../../src/pages/Tasks.tsx) — задачи из плана получают бейдж
  "🤖 План дня" (title = причина от AI) и янтарную подсветку строки

## Ограничения

- Не различает "сегодня из плана уже сделано" и "сегодня из плана ничего не предлагалось" в сторону
  UI — оба случая после выполнения всех задач показывают пустой список, но с разным текстом
  (`allDone` считается по тому, был ли `todayPlan.length > 0` изначально).
- Один день — один план; нельзя держать несколько альтернативных вариантов одновременно.
